# نظام النسخ الاحتياطي اليومي

يتكوّن النظام من طرفين:

- `supabase/functions/daily-export/index.ts`: دالة محمية بـ `DAILY_SYNC_TOKEN` تُرجع `products` و`production` و`shipments` و`activity` و`profiles` الآمنة و`permissions`، مع تحميل متدرج لكل جدول لتجاوز حد 1000 صف.
- `backup/google-apps-script.gs`: يحدّث Google Sheet المرتبط، ثم يحدّث ملف Excel ثابتًا، ولا يسجل نجاح المزامنة إلا بعد اكتمال الخطوتين.

لا يتطلب هذا النظام أي migration أو DDL.

## Script Properties

احتفظ بالأسماء التالية كما هي داخل مشروع Apps Script:

- `DAILY_EXPORT_URL`
- `DAILY_SYNC_TOKEN`
- `SUPABASE_PUBLISHABLE_KEY`
- `LAST_SYNC_AT` — يكتبه السكربت بعد نجاح كامل العملية.
- `XLSX_FILE_ID` — يكتبه السكربت عند أول إنشاء، ثم يحدّث الملف نفسه في التشغيلات التالية.
- `BACKUP_FOLDER_ID` — اختياري، ويستخدم فقط عند إنشاء ملف Excel لأول مرة.

لا تطبع `DAILY_SYNC_TOKEN` ولا تضعه داخل المستودع. الـpublishable key لا يحل محله؛ التوكن يُرسل في جسم POST.

## التبويبات

يحدّث السكربت هذه التبويبات، ويملأ `Production Backup` من نفس صفوف الإنتاج المقروءة بدل تركه فارغًا:

1. لوحة التحكم
2. الملخص اليومي
3. الإنتاج
4. الرولات المستخدمة
5. الشحنات
6. المنتجات
7. سجل النشاط
8. المستخدمون
9. الصلاحيات
10. Production Backup

الصفوف الفارغة استجابة صحيحة؛ تبقى العناوين والتنسيقات موجودة حتى عندما تكون جميع المصفوفات فارغة.

## النشر والتشغيل اليدوي

1. انشر المصدر المحلي المحدّث لـ`daily-export` بالطريقة المعتادة للمشروع من دون تشغيل migrations.
2. الصق الملف الكامل `google-apps-script.gs` في مشروع Apps Script المرتبط بالشيت الحالي.
3. راجع Script Properties أعلاه من دون عرض قيمة التوكن في السجلات.
4. شغّل `runDailyExport` يدويًا ووافق على صلاحيات Sheets وDrive وطلبات HTTP عند الحاجة.
5. تأكد من أن نتيجة التشغيل تعرض `ok: true` وأعداد الإنتاج والشحنات والمنتجات والمستخدمين والصلاحيات ومعرّف ملف Excel.
6. افتح التبويبات التسعة وتحقق من البيانات العربية والتنسيق RTL وتفاصيل النايلون والتالف والرولات.
7. افتح ملف Excel ذي المعرّف الموجود في `XLSX_FILE_ID` وتأكد أن كل التبويبات والقيم موجودة، ثم شغّل المزامنة مرة ثانية وتأكد أن المعرّف لم يتغير ولم ينشأ ملف مكرر.

## الـTrigger اليومي

شغّل `installDailyTrigger` مرة واحدة فقط. ينشئ trigger لـ`runDailyExport` يوميًا قرابة الساعة 23:00 بتوقيت `Asia/Hebron` إذا لم يكن موجودًا. إذا وجد أكثر من trigger، يتوقف ويطلب حذف الزائد يدويًا بدل إنشاء المزيد.

شغّل `getDailyTriggerStatus` وتحقق من:

- `exists: true`
- `count: 1`
- `handler: runDailyExport`
- `timezone: Asia/Hebron`
- وجود قيمة `lastSyncAt` بعد نجاح التشغيل اليدوي

راجع أيضًا صفحة Apps Script → Triggers للتأكد من آخر تشغيل وموعد التشغيل التالي؛ واجهة Apps Script هي المرجع لهذه المعلومات التي لا يوفرها كائن الـtrigger برمجيًا بالكامل.

## معايير النجاح اليدوية

HTTP 200 وحده لا يكفي. يعتبر الاختبار ناجحًا فقط بعد التحقق المباشر من Google Sheet وملف Excel والـtrigger. اختبر مرة ببيانات فعلية فيها أكثر من عنصر نايلون شفاف ومطبوع ووصف/وزن تالف، ومرة بقاعدة فارغة إن أمكن. لا تعدّل `LAST_SYNC_AT` يدويًا؛ يجب ألا تتغير إذا فشلت كتابة أي sheet أو تحديث Excel.
